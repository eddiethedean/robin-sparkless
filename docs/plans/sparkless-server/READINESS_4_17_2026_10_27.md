# Phase 4.17 release readiness follow-up — 2026-10-27

**Status: HOLD.** This follow-up updates the original review in [READINESS_4_17.md](READINESS_4_17.md) for release PR [#1727](https://github.com/eddiethedean/robin-sparkless/pull/1727). The Rust source compatibility, SQL planning admission, candidate artifact behavior, and Python minimum findings are repaired or resolved below. Publication remains blocked by the downstream Rust dependency audit and the final exact-candidate gates.

## Findings

| Finding | Current disposition |
| --- | --- |
| R1 — vulnerable compression crates in published Rust consumers | **Open release blocker.** The consumer-graph gate removes the workspace `[patch.crates-io]` table and resolves dependencies as a downstream Cargo user would. Its fresh audit (advisory database updated 2026-10-27) finds `zstd 0.13.3` (RUSTSEC-2026-0391) and `zstd-safe 7.3.0` (RUSTSEC-2026-0403 and RUSTSEC-2026-0398). The merged [Polars fix](https://github.com/pola-rs/polars/pull/30316) is not represented by this release's resolved consumer graph. The machine-readable audit is [4.17-rust-consumer-audit-2026-10-27.json](evidence/4.17-rust-consumer-audit-2026-10-27.json), SHA-256 `90696d7903328e5d570a3dcddcc129b9a3177ffa1d7e898e4be3e59e4f5ade6a`. Do not publish until the dependency update is included in the crates.io consumer graph and the release audit passes. |
| R2 — `StructField` minor-release source break | **Repaired.** `StructField` retains its original three public fields and constructor. Metadata uses additive `LogicalField`/`StructType::from_logical_fields`/`logical_fields` APIs and `DataType::LogicalStruct`, with the established JSON `Struct` tag preserved. Source-compatibility and metadata round-trip fixtures cover both APIs. |
| R3 — SQL parser work on Tokio workers | **Repaired.** SQL validation now reserves bounded admission first and runs in `spawn_blocking` while retaining the compute permit and admission ticket. The regression covers health responsiveness, capacity rejection, and exact mutation replay while planning is queued. |
| R4 — packaged `server` extra and container checked only for health | **Repaired in release gates.** Server-extra, candidate container, and public container checks exercise SQL and mutation/replay/status behavior. |
| R5 — installed Rust server binary only checked for version | **Repaired in release gate.** The exact binary produced by `cargo install` is passed to the control, health, SQL, mutation, replay/status, and graceful-shutdown verifier. |
| R6 — Python 3.8 syntax despite a claimed lower minimum | **Policy resolved for 4.17.** Both Python distributions require `>=3.11`; the extension uses `abi3-py311`; release builds and source builds use Python 3.11; the test matrix uses Python 3.11–3.14. Python 3.8–3.10 are no longer supported or shipped. Current compatibility-matrix docs and defaults were updated accordingly. Historical 4.16 recovery pins remain unchanged. |
| C1 — standalone contract was staged | **Resolved.** Implemented 4.17 decisions are frozen in [DECISIONS.md](DECISIONS.md), including standalone scope, HTTP protocol, schema, identifier behavior, and Python 3.11 support. |
| C2 — complete final candidate evidence | **Pending.** The non-publishing release workflow must pass at the final branch head, including V15–V18, V31, exact candidate distributions, the security gate, and fresh consumer checks. |
